# Bug Bounty Workflow — Compatibility Entry Point

This skill name is retained to preserve existing skill references and trigger compatibility. The complete, canonical workflow is [../SKILL.md](../SKILL.md).

Use that methodology to choose the appropriate next step across:
- scope verification and target understanding;
- asset, endpoint, JavaScript, identity, and technology mapping;
- disclosed-report research and threat modeling;
- hypothesis-driven vulnerability testing, including web, API, business-logic, cloud, and AI features;
- evidence-based cross-layer chaining;
- false-positive rejection, validation, severity, and reporting handoff.

Do not interpret this broad catalog as an instruction to test every vulnerability class on every target. Select a specialist skill only when the target evidence provides a relevant signal. Preserve negative results and target observations in the learning layer, not by modifying this skill.

For payloads, bypasses, wordlists, or pattern references, load `security-arsenal` only when needed. Final submission eligibility and report requirements remain owned by the dedicated validation/triage and reporting skills.
